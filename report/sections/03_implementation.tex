\section{Object Detection}
In order to localize the ski jumper within each video frame, we employed an object detection technique based on convolutional neural networks. Specifically, we selected the YOLOv8 architecture for this task. 

\subsection{Fine-tuning}
To acquire the optimal model for ski jumper detection, we utilized fine-tuning to adapt a pre-trained YOLOv8 model. The goal was to recognize the jumper's bounding box with the highest possible accuracy.

This task required a well-defined and precise dataset. To construct this, we extracted frames from experimental videos at random time intervals ranging from 500 ms to 2500 ms. This sampling strategy ensured diverse temporal coverage of the entire jump sequence. As a result of this extraction process, we obtained a base dataset of 991 frames.

Following extraction, we proceeded with the annotation of the data using the \href{https://app.roboflow.com/skijumpinglabeling/skijumping/2}{Roboflow} platform. Bounding boxes were drawn tightly around the jumper to minimize background noise and exclude unnecessary margins. Additionally, we included 16 unannotated frames (background only) to improve the model's robustness against false positives.

To prevent overfitting and improve the model's generalization capabilities regarding angle and lighting conditions, we applied data augmentation. Specifically, we utilized rotation (between -15\textdegree{} and +15\textdegree{}) and brightness adjustment (between -15\% and +15\%). 

For training and validation purposes, the augmented dataset was split as follows:
\begin{itemize}
    \item \textbf{Train set:} 2294 images (91\%)
    \item \textbf{Valid set:} 159 images (6\%)
    \item \textbf{Test set:} 67 images (3\%)
\end{itemize}

With the dataset prepared, we proceeded with fine-tuning using the following configuration:
\begin{enumerate}
    \item \textbf{Model Selection:} Initialization of the pre-trained YOLOv8 Nano (\texttt{yolov8n.pt}) as the starting checkpoint.
    \item \textbf{Training Execution:} The training was executed via the \texttt{model.train()} function with 100 epochs, an image size of 640 pixels, using an NVIDIA T4 GPU (Device 0).
\end{enumerate}

The process yielded a highly effective model, confirmed by the final performance metrics:
\begin{itemize}
    \item \textbf{mAP50 (0.992):} Indicates that the model almost always detects the jumper accurately.
    \item \textbf{mAP50-95 (0.817):} Suggests that the predicted bounding boxes align precisely with the jumper and their equipment.
    \item \textbf{Precision (0.983) and Recall (0.975):} Confirms that the model produces very few false positives and successfully identifies the jumper in nearly every frame.
\end{itemize}

\subsection{Detection Pipeline}
Leveraging the fine-tuned model, we constructed a pipeline for continuous detection and tracking across video frames.

The pipeline processes the video frame-by-frame. First, the YOLO model localizes the jumper. In cases where the model detects multiple targets, the system selects the bounding box with the highest confidence score. To maintain continuity, we utilized YOLO's object tracking capabilities, assigning a unique ID to the detected subject to distinguish the continuous trajectory from momentary detection artifacts.

To determine the jumper's precise Center of Mass (CoM), we integrated the Segment Anything Model (SAM). SAM is an advanced segmentation model capable of separating the jumper from the background with high pixel-level precision. Since SAM is computationally intensive, it is applied only within the bounding box coordinates provided by YOLO (the Region of Interest). Using the precise segmentation mask generated by SAM, the model calculates the exact geometric center of the jumper.

However, the raw CoM coordinates calculated frame-by-frame often exhibit high-frequency noise or "jitter" due to minor segmentation fluctuations. To address this, we implemented a Kalman filter to estimate and smooth the jumper's trajectory.  The Kalman filter predicts the future position of the point based on previous states and corrects it using the current measurement. Consequently, the final tracking point moves smoothly, as the filter effectively mitigates noise by statistically weighing the predicted state against the measured position.

\section{Slope model}
The objective of this section of the code is the procedural generation of a ski jump profile based on geometric parameters.

The class \texttt{Profile Database} contains a predefined dictionary featuring data for Obersdorf and Garmisch-Partenkirchen hills. It sotres key dimensions including:
\begin{itemize}
    \item \textbf{\texttt{H}}, \textbf{\texttt{N}} - total height and tower height
    \item \textbf{\texttt{inrun\_angle}}, \textbf{\texttt{takeoff\_angle}}, \textbf{\texttt{landing\_angle}} - incline angles
    \item \textbf{\texttt{inrun\_length}}, \textbf{\texttt{takeoff\_length}}, \textbf{\texttt{Hill Size}}, \textbf{\texttt{K-point}} - characteristic lengths
\end{itemize}

To accurately represent the curves of the hill, the project utilizes \textbf{Cubic Hermite Interpolation}. This is mathematical component that allows the curve to be defines by specifying endpoints and the desired slopes at those points.

The \texttt{HillModel} class acts as the computational engine, translating \texttt{DataModel} parameters into \textit{(x, y)} coordinates. The coordinate system is anchored so that \textit{x} = 0 marks the start of the takeoff table.

\section{Camera switch detection}
The objective of this module is to automatically analyze ski jumping video footage to detect montage cuts (shot changes). The program segments the recording into logical sequences corresponding to different camera angles, allowing targeted analysis of a specific phase of the performance.

To handle video clips efficiently, the module implements several pre-processing optimizations:
\begin{itemize}
    \item \textbf{Downscaling} - Frames are resized to a width of 320 pixels.
    \item \textbf{HSV Color Space} - Analysis is performed on Hue-Saturation histogram.
    \item \textbf{Normalization} - Histograms are normalized using Min-Max scaling, making the comparison independent of the total pixel count.
\end{itemize}

The core shot change detection algorithm involves comparing the histogram of consecutive frames to identify significant visual changes.

Raw detection data is processed into logical camera intervals. The module includes a heuristic layer that attempts to classify the shot type based on the sequence and duration of the intervals. Classification based on the number if detected scenes and the position in the sequence assigns sementinc lables to the shots:
\begin{itemize}
    \item \texttt{Start} - The athlete at the starting bar.
    \item \texttt{Acceleration/Acceleration A/B} - the inrun phase
    \texttt{Jump} - The flight and landing phase
\end{itemize}

\section{Homography from camera plane to the scene}\label{Homography}
This subsection is responsible for extracting specific geometric features from the video footage in order to calculate the angle and the distance between the camera plane and the plane of the jumper in some frame. This module uses additional functions of the shot detection phase, find \texttt{\_inrun\_frame} and \texttt{find\_landing\_frame}. Those functions output the most feasible frames (indexes) for the calculations. This feasibility was chosen by empiric experiments and are based on the time:
\begin{itemize}
    \item Inrun Frame - extracted at 10\% of the duration of the \textit{Acceleration} phase. This point is chosen to ensure the camera has settled on the athlete, while the inrun tracks remain clearly visible before the camera pans significantly.
    \item Landing Frame - extracted at 85\% of the duration of the \textit{Jump} phase. This timing typically captures the landing area (K-point and HS lines) just as the athlete approaches the ground, ensuring that the relevant ground markings are in the field of view.
\end{itemize}

\subsection{Inrun Track Detection}
The detection of the parallel tracks on the inrun relies on the classical computer vision techniques.
\begin{itemize}
    \item \textbf{Color Segmentation} - The image is converted to the HSV color palette. A threshold filter targets white pixels with values: H: 60-100, S: 15-30, V (200-255).
    \item \textbf{ROI Masking} - To reduce noise, a geometric mask zeroes out the peripheral regions of the image, focusing the detector on the center where the tracks are expected.
    \item \textbf{Morphological Filtering} - A sequence of \textit{Opening} and \textit{Closing} operations is applied using elliptical kernel.
    \item \textbf{Line Extraction} - The canny edge detector finds high-gradient boundaries, which are then transformed into line segments using the \texttt{Probabilistic Hough Transform}.
    \item \textbf{Eliminating close detections} - special function computes the distance between the lines to eliminate very close detections which represents the same information from the image.
    \item \textbf{Pairing} - The resulting lines are passed to the function that takes into the consideration the distance between them and the position in the frame, and output the best pair of lines.
\end{itemize}

\subsection{Inrun Steps Detection}
To assist in camera calibration, the system also detects the service stair parallel to the inrun tracks.
\begin{itemize}
    \item \textbf{Region of Interest} - Processing is strictly limited to the bottom-right part of the image, where stairs are typically located in broadcast angles.
    \item \textbf{Directional Filtering} - A morphological kernel of size (31, 1) is used. This kernel preserves features that span across the image while eroding vertical noise.
    \item \textbf{Filtering} - Detected lines are filtered to ensure they are approximately horizontal.
    \item \textbf{Choosing feasible pair} - very close lines are eliminated, and the best pair is picked up in the analogous way as in the inrun track detection.
\end{itemize}

\subsection{Detection of the K and HS lines}
Unlike the previous features, the detection of the K-point and Hill Size (HS) lines on the landing hill proved significantly more challenging and could not be reliably handled by traditional computer vision methods. Consequently, we decided to employ a deep learning approach for this task.

To train a model for this segmentation task, we extracted and annotated 400 images. We applied data augmentation techniques, including rotation (between -8\textdegree{} and +8\textdegree{}) and brightness adjustment (between -8\% and +8\%), which expanded the dataset to 970 images. This dataset was split into an \textbf{88\% training set}, a \textbf{7\% validation set}, and a \textbf{5\% test set}.

By fine-tuning the YOLOv8-seg architecture, we successfully trained a segmentation model to identify the regions corresponding to the K-line and the HS-line. As a result of the segmentation process on the landing frame, we obtain two binary masks: one representing the K-line and the other the HS-line.

For each detected mask, the system calculates the optimal line parameters $(a, b)$ using a least-squares fit on the mask's pixel coordinates. This provides a robust mathematical representation of the line in the form $y = ax + b$.

Finally, we constructed a complete pipeline to extract these lines from specific frames:
\begin{enumerate}
    \item The video is loaded and changes are detected in the shot.
    \item Recall the specific frames for the inrun and landing.
    \item Extract the lines using the trained model and linear fitting.
\end{enumerate}
